# POTATO SURVIVORS

> Brotato 스타일 로그라이트 서바이버 — Unity 6 / C# 개인 포트폴리오 프로젝트

한 판 안에서 **무기를 모으고 강화하며 밀려오는 몬스터를 버티는** 탑다운 서바이버 게임입니다.
웨이브 전투와 웨이브 사이 상점 루프를 중심으로, **데이터 주도 설계**와 **자동화 QA**를 직접 구축했습니다.

## 게임플레이 흐름

```
메인 로비 (시작 무기 선택)
      ↓
   웨이브 전투 (자동 공격 · 몬스터/보스 스폰)
      ↓  20초 경과
     상점 (무기 강화 · 아이템 · 리롤)
      ↓  다음 라운드
   웨이브 전투 (난이도 상승) …
      ↓  플레이어 사망
   게임오버 (재시작 / 로비 복귀)
```

- **시작**: 로비에서 시작 무기를 골라 진입
- **전투**: 장착 무기가 근처 적을 자동 조준·공격. 몬스터 처치 시 코인 드랍
- **성장**: 코인으로 상점에서 무기 강화(레벨)·아이템 구매·무기 조합(세트 효과)
- **진행**: 스테이지가 오를수록 스폰·HP 상승, 주기마다 보스 등장

## 주요 시스템 & 아키텍처

### 무기 시스템
- **6슬롯 자동 공격** — 감지 범위 내 최근접 적을 자동 조준
- **데이터 주도** — 모든 무기 스펙을 `WeaponData`(ScriptableObject)로 분리, 코드 수정 없이 무기 추가
- **레벨 강화** — 같은 무기 중복 획득 시 레벨업(최대 5), 레벨당 데미지·관통 상승
- **행동 전략화** — `IWeaponBehavior` 인터페이스로 근접 스핀 / 원거리 투사체(관통·다발) 분리 (Strategy 패턴)
- **세트 효과** — 장착한 근접/원거리 무기 개수 2·4·6에 따라 해당 타입 데미지 보너스

### 몬스터 · 스폰
- **오브젝트 풀링** — `ObjectPoolManager`로 몬스터·투사체·코인 재사용, 런타임 Instantiate/Destroy 최소화
- **가중치 스폰 테이블** — 종류별 출현 확률·최소 스테이지 지정
- **웨이브 / 스테이지** — `StageManager`(싱글톤)가 시간 기반 웨이브 진행, 스테이지 스케일(HP·스폰 간격)과 보스 주기 관리
- **화면 기준 스폰** — 카메라 뷰 안에서만 스폰, 플레이어 근접 영역 제외

### 재화 · 상점
- **코인 자석 획득** — 일정 범위 내 코인이 플레이어에게 흡인
- **혼합 상점** — 무기(보유 레벨 기준 "다음 레벨" 카드) + 아이템 카드를 함께 제시
- **등급 & 행운** — 아이템 등급(노말/에픽/유니크)을 행운 스탯 가중치로 추첨

### UI
- **런타임 자가 생성 UI** — 로비·HUD·상점·게임오버 UI를 코드로 구성해 에디터 조립 의존을 최소화
- **이벤트 기반 갱신** — 체력·재화·무기·웨이브 변화가 이벤트로 UI에 전파(폴링 없음)

### 설계 패턴 & 원칙
| 패턴 / 원칙 | 적용 |
|---|---|
| Singleton | `StageManager`, `ObjectPoolManager` |
| Object Pool | 몬스터·투사체·코인 재사용 |
| Observer (Event) | `OnHealthChanged` / `OnWeaponsChanged` / `OnWaveCleared` → UI 자동 갱신 |
| Strategy | `IWeaponBehavior` (근접/원거리) |
| Data-Driven | `WeaponData`·`ItemData`·`LobbyConfig`·`ShopCatalog`·`SpawnConfig` (ScriptableObject) |

> **배선 최소화**: 설정을 Resources의 ScriptableObject로 두고 런타임에 자동 로드해, 씬 인스펙터 수동 연결 없이 동작하도록 설계했습니다. → 휴먼 에러(연결 누락)를 구조적으로 줄임.

## QA / 테스트

게임 구현과 별개로 **품질 검증 프로세스**를 직접 설계·운영했습니다.

### 1) 자동화 테스트 (Unity Test Framework)
- 게임 코드를 `Game` 어셈블리로, 테스트를 `GameTests.EditMode` 어셈블리로 분리
- 검증 로직을 순수 함수(`WeaponMath` 등)로 추출해 **플레이 없이** 빠르게 검증
- 커버: 무기 레벨별 데미지 공식, 관통 증가, 세트 단계(2/4/6), 확률/기본값
- 효과: 밸런싱·리팩터 중 규칙이 깨지면 **즉시 FAIL로 회귀 감지**

### 2) 수동 QA — 테스트 케이스
- 전 기능을 아우르는 **테스트 케이스 55개**를 스프레드시트로 작성 (사전조건·절차·기대결과·결과·비고)
- 1회차 실행에서 **버그 6건 발견** → 원인 분석 → 수정 → 재검증

### 3) 디버그 콘솔 (F1)
- 골드/스테이지 점프/보스 소환/무적/즉사/배속/무기 지급을 즉시 조작
- 특정 상황(보스전, 세트 6개 등) 재현 시간을 크게 단축
- 에디터·개발 빌드에서만 생성(배포 빌드 미포함)

## 문제 해결 사례

> 형식: **문제 → 원인 / 접근 → 해결 → 얻은 점**

### 1. Animator Controller가 "Broken PPtr"로 깨짐
- **문제**: 코드로 생성한 애니메이터 컨트롤러를 Unity가 로드하지 못하고 참조가 깨짐
- **원인/접근**: 내부 오브젝트 `fileID`가 부호 있는 64비트 정수 범위를 초과. Unity YAML 직렬화 규칙을 역추적
- **해결**: `fileID`를 안전 범위로 재생성하도록 규칙을 잡아 자산 재작성
- **얻은 점**: Unity의 에셋 직렬화·`fileID`/GUID 참조 구조를 실제로 이해하게 됨

### 2. 코드를 자동 테스트할 수 없는 구조
- **문제**: 테스트 어셈블리에서 게임 코드를 참조할 수 없어 단위 테스트 작성 불가
- **원인/접근**: 모든 코드가 기본 `Assembly-CSharp`에 있었고, 어셈블리 정의(asmdef) 기반 테스트 어셈블리는 이를 참조할 수 없음
- **해결**: 게임 코드를 `Game.asmdef`로 분리하고, 계산 로직을 순수 함수(`WeaponMath`)로 추출해 테스트 대상으로 만듦
- **얻은 점**: "테스트 가능한 구조"가 곧 결합도 낮은 설계임을 체감. 어셈블리 분리·의존성 관리 경험

### 3. 프리팹 스프라이트를 바꿔도 반영 안 됨
- **문제**: 프리팹의 스프라이트를 교체했는데 플레이 화면은 그대로
- **원인/접근**: 씬에 배치된 프리팹 **인스턴스의 오버라이드**가 프리팹 원본보다 우선 적용되고 있었음
- **해결**: 씬 인스턴스의 오버라이드 값을 직접 정정
- **얻은 점**: 프리팹 ↔ 인스턴스 오버라이드 우선순위와 직렬화 방식 이해

### 4. 보스가 영구히 등장하지 않음 (QA 발견)
- **문제**: 보스 주기(5스테이지)에 도달해도 보스가 나오지 않음
- **원인/접근**: 스포너의 `bossPrefab` 슬롯이 인스펙터에서 **연결 누락**(빈 참조). 스폰 조건 코드는 정상
- **해결**: 보스 참조를 Resources의 `SpawnConfig`(ScriptableObject)에 담아 **런타임 자동 주입** — 인스펙터 배선 의존 자체를 제거
- **얻은 점**: 수동 연결은 휴먼 에러의 원천. 데이터 주도로 "연결 안 해도 동작"하게 만들어 재발 방지

### 5. 상점·HUD에 아이콘 없는 빈 무기가 노출 (QA 발견)
- **문제**: 일부 무기 카드/슬롯이 아이콘 없이 빈칸으로 표시
- **원인/접근**: 상점 후보 목록에 아이콘이 없는 **구버전 임시 무기**가 남아 있었음. 진열 목록의 출처가 여러 곳이라 관리가 어긋남
- **해결**: 진열 목록의 **단일 출처(카탈로그)** 를 정본으로 삼아, 임시 무기를 구조적으로 배제
- **얻은 점**: 단일 진실 공급원(Single Source of Truth)의 중요성

## 회고

- **혼자서 4주** 동안 기획부터 구현·QA까지 한 사이클을 끝까지 돌려본 프로젝트입니다.
- 초반엔 기능을 씬에 직접 연결하다 연결 누락 버그를 여러 번 겪었고, 이후 **데이터 주도 + Resources 자동 로드**로 전환하면서 "배선하지 않아도 동작하는" 구조의 이점을 체감했습니다.
- 후반에는 **QA를 별도 축으로** 세워 자동 테스트·테스트 케이스·디버그 도구를 만들었고, 실제로 이 과정에서 스스로 버그 6건을 잡아냈습니다. 구현과 검증을 분리해서 보는 시야가 생겼습니다.
- 본 프로젝트는 **AI 페어 프로그래밍(Claude)** 을 적극 활용했습니다. 반복적인 보일러플레이트·에셋/YAML 작성은 AI로 가속하고, **시스템 구조 설계·기능 우선순위·QA 검증은 직접 주도**하는 방식으로 진행했습니다. AI를 도구로 다뤄 개발 속도를 끌어올리는 경험 자체도 이 프로젝트의 수확이었습니다.
